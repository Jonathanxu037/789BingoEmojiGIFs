聊天表情面板 GIFs 模块需求文档
2026年9月23日需求负责人 @Joshua版本 V1.0查看交互原型 →

一、需求概述

在聊天表情面板最前面新增「GIFs」分页，展示官方动画表情，用户点击即可发送；原「GIFs」分页更名为「Search」并移至最后。

动画表情素材由设计侧产出后上传至服务端，前端通过接口获取并展示，素材增减无需客户端发版。本需求覆盖 iOS App、Android App、小程序/H5，三端功能一致。

二、面板结构

现版面板只有 Stickers、GIFs 两个分页，改版后为三个：

顺序分页内容本期变更
1GIFs官方动画表情新增
2Stickers现有贴纸表情无
3Search第三方动图检索（原 GIFs）仅更名
  • 分页样式沿用现有分段控件，由两等分改为三等分。
  • GIFs 分页图标与选中态由设计侧提供。
  • 面板默认选中的分页待产品确认。

三、GIFs 分页

  1. 进入分页即展示官方动图，无需搜索；分组与先后顺序以服务端返回为准。
  2. 网格排列，移动端每行 3 列，图片等比居中裁剪，尺寸以设计稿为准。
  3. 列表展示静态缩略图，避免同屏大量动图同时播放。
  4. 点击直接发送，不弹二次确认；发送后面板保持展开，支持连续发送。
  5. 长按放大预览并播放动图，松手关闭，不触发发送。
  6. 发送后的消息在会话中以动图循环播放。
  7. 加载中展示占位图；单个素材加载失败时保持占位且不可点击；整页加载失败时展示重试。

四、Search 分页

功能保持不变，仅名称与位置调整。分页标题、搜索框占位文案、空态与错误文案中的「GIFs」字样需排查替换；埋点需区分新旧两个分页。

五、表情素材与元数据管理

表情的上线与变更走线下流程：产品定批次与分组，设计出素材，技术上传并登记元数据，测试核对后发布生效。

确定上线批次
→
设计产出素材
→
规范与内容审核
→
上传并登记元数据
→
测试核对
→
发布生效
审核不通过 → 退回「设计产出素材」重新修改

元数据

每个表情需登记：唯一标识、名称（按需多语言）、所属分组、组内排序、状态（待上线 / 已上线 / 已下架），节日类表情可额外登记生效与失效时间。分组需登记：名称、图标、排序、状态。

管理规则

  1. 只有「已上线」的表情与分组会出现在面板中。
  2. 表情下架后不再展示，已发送的历史消息仍正常展示。
  3. 替换素材时表情标识保持不变，客户端需能拿到新图。
  4. 发布后客户端无需发版即可看到变化。
  5. 每次上线、替换、下架都需记录操作人、时间与变更内容。

六、验收标准

面板按 GIFs、Stickers、Search 顺序展示，选中态正确。
GIFs 分页无需搜索即可浏览并发送，双方会话均正常播放。
服务端新增、替换、下架表情后，客户端无需发版即可看到变化。
表情下架后历史消息仍正常展示。
iOS、Android、小程序/H5 三端表现一致。
弱网与加载失败时有占位与重试，不白屏不崩溃。
待确认：面板默认选中分页、首批上线的分组与数量、名称多语言覆盖范围。
